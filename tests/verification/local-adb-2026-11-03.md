# On-device wireless ADB verification — 2026-11-03

Experimental, Debug only. Tested on the isolated Pixel 7 ARM64 Android 15 / API 35 emulator (`emulator-5580`) using package `lifeos.md.tapilot.e2everify`.

The workstation installed the APK, drove visible UI interactions and collected screenshots/diagnostics. **It did not run `adb pair`, `adb connect`, the helper starter script, or a shell-helper launch command.** Pairing and helper bootstrap were performed by the app against its own loopback ADB daemon.

## Observed steps

1. Enabled Developer options and Wireless debugging in Android Settings. Authorized the emulator's Wi-Fi network using the system dialog.
2. Put Tapilot and Settings in split screen using the system Recents menu. Opened the system pairing-code dialog and entered its port/code in Tapilot. The system dialog closed after the app paired successfully. [Result](local-adb-2026-11-03/pairing-result.png). Pairing codes are intentionally excluded from committed screenshots.
3. Entered the connection port and attempted helper startup **without app consent**. The app rejected it and required explicit authorization. [Consent gate](local-adb-2026-11-03/consent-required.png).
4. Returned to full screen, authorized the shell helper, entered the connection port and tapped Connect. The app received the shell-owned Binder, showed connected status and enabled Start. A read-only process check showed the helper running as UID 2000.
5. Created a virtual display and opened its floating preview. Tapping the fixture in that preview changed its actual counter from 0 to 1. [Successful input](local-adb-2026-11-03/local-tap-success.png).
6. Revoked consent with the display active. The helper process ended, the overlay disappeared, Start became disabled, and display diagnostics showed only display 0. [Revoked](local-adb-2026-11-03/local-revoked.png).
7. Granted fresh consent and reconnected using the persisted app identity, without entering another pairing code. Startup succeeded again.
8. Created another floating display, then disabled emulator Wireless debugging as a transport-loss fault injection. The app closed the session and display and disabled Start. [Disconnected](local-adb-2026-11-03/wireless-disconnected.png).
9. Selected Forget local pairing key. The app reported deletion, and a file-existence check confirmed that the private identity file was absent. [Forgotten](local-adb-2026-11-03/forgotten.png).

## Checks

- Android Debug assembly and lint passed.
- Android unit tests: 406 total, 405 passed, 1 existing skip, zero failures/errors.
- New tests cover valid/invalid ports, remote-host and command rejection, six-digit codes with leading zeros, command argument quoting, consent expiry, and bidirectional pairing transport closure on deadline.
- Runtime bundle preparation: 130 tests passed.
- Supplemental library notices are packaged with the Debug dependencies. Beta/Release do not include the local ADB client.

## Limits

This is emulator evidence, not OPPO or Redmi validation. Android 12+ is required by the existing helper handoff. The initial phone-only UI requires split screen to keep the system pairing-code dialog alive. OEM behavior, wireless port changes across device reboots, and production background Agent execution are not established by this run. The existing computer bootstrap remains an optional fallback.
